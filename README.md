# 供方智选：供应商需求匹配原型

一个结合供应商管理实习场景制作的本地个人项目原型。它将“资源池筛选、资格字段初筛、采购需求匹配、候选排序和人工复核”串成一条可解释的演示链路。

项目借鉴了供应商资源池维护、资格初筛、采购比较和风险提示等通用工作环节，适合作为对业务流程的轻量抽象。它**不等同于正式供应商认证、履约评估或采购决策系统**，也不复制雇主内部审批层级、阈值、名单或供应商资料。

开发时使用 Codex AI 编程助手协助把需求拆成页面和功能、生成初版代码，并围绕 Excel 导入、数据校验、资格硬筛和结果说明逐步迭代。业务流程取舍、数据边界和最终表述由项目作者审阅确定。应用运行时不调用大语言模型 API；文本匹配使用传统 NLP 方法。演示数据均为虚构数据，不来自雇主或真实采购交易。

## 演示流程

1. **资格字段初筛：**根据表格中人工录入的资格状态、经营范围匹配和黑名单标记执行硬性过滤。待核验或不符合条件的记录不会进入后续排序，并显示原因。
2. **筛选候选范围：**在通过资格字段初筛的记录中，按品类和服务区域缩小候选集合。
3. **需求匹配与候选排序：**用字符级 TF-IDF 和余弦相似度计算采购需求与供应商描述的文本相关度；再结合价格、质量、准时交付率、合规分和交期进行可调权重排序。
4. **查看依据并人工复核：**展示分项指标和规则风险提示，支持导出候选排序结果，供采购人员核对原始材料和业务情况。

## 功能

- 支持 CSV 和 Excel 工作簿（.xlsx）导入，Excel 可选择工作表。
- 检查必需字段、空名称、非数字值和评分范围；无效数据行会提示并跳过。
- 按品类、服务区域过滤资源池。
- 资格初筛状态支持“通过/不通过/待核验”；经营范围支持“匹配/不匹配/待核验”；黑名单字段支持“是/否/待核验”。
- 对通过资格字段初筛的记录计算文本相关度和加权排序分。
- 可调整排序权重与质量、准时交付率、合规分的风险提示阈值。
- 显示暂不进入候选排序的记录及原因，并导出当前候选结果 CSV。

## 本地运行

需要 Python 3.10 或更新版本。

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开 Streamlit 显示的本地地址即可。macOS/Linux 可使用 `source .venv/bin/activate` 激活虚拟环境。

## 数据字段

CSV 或 Excel 工作表首行需包含以下字段，可复制并扩展 `suppliers.csv` 模板。

| 字段 | 含义和格式 |
| --- | --- |
| `supplier` | 供应商名称，必填 |
| `category` | 品类，必填 |
| `regions` | 服务区域，多个区域用分号分隔，例如“深圳;东莞” |
| `products` | 产品或服务描述文本 |
| `certifications` | 资质描述文本 |
| `qualification_status` | 人工初筛状态：通过、不通过、待核验 |
| `scope_match` | 人工判断经营范围是否匹配：匹配、不匹配、待核验 |
| `blacklisted` | 人工录入的黑名单标记：是、否、待核验 |
| `unit_price` | 非负数；用于排序的候选应采用可比计价单位 |
| `quality_score` | 0–100 的示例输入分 |
| `on_time_rate` | 0–100 的示例准时交付率，例如 95 表示 95% |
| `compliance_score` | 0–100 的示例输入分 |
| `lead_days` | 非负交期天数 |

空值或无法识别的资格标记会归为“待核验”，不会默认通过。格式校验不等于核验营业执照、资质证书、信用信息、关联关系或黑名单原始记录。

## 排序逻辑

字符级 2–4 gram TF-IDF 对采购需求与品类、服务区域、产品和资质描述做字面片段比较，再用余弦相似度得到 0–100 的需求相关度分。它不理解同义词和上下文，也不代表准确率或中标概率。

价格和交期只在当前通过资格字段筛选并满足品类/区域条件的集合内做相对归一化，不能跨品类或不同计价单位直接比较。质量、准时交付率和合规分直接使用导入表中的数值。各项按页面设置的权重计算排序分；权重可调，但没有用历史采购结果校准。若同一候选集合的价格或交期完全相同，该项统一记为 100 分。

风险提示依据页面上的可调阈值标记输入指标，不是 AI 预测，也不替代制度规定的审核或审批。候选排序仅用于辅助查看和讨论，最终判断应由采购人员结合原始材料与业务情况作出。

## 原型边界

- 资格结论、经营范围和黑名单状态由使用者录入；程序只执行明确的字段规则，不做材料真实性审查或外部信息查询。
- 本项目没有实现正式的两阶段资格认证与能力认证，也没有实现历史履约分级、证照有效期预警、退出/黑名单审批、采购审批流、权限控制、审计日志或企业系统集成。
- 质量、交付和合规分是演示输入，不代表雇主内部正式评估指标或真实供应商档案；排序权重和风险阈值也不是制度标准。
- 示例供应商数据均为虚构数据。正式采购仍须按组织制度完成资格与能力审核、资料留档、履约评估和人工决策。

## AI 辅助开发说明

这个项目适合展示“如何用 AI 编程助手把业务问题转成可运行原型”，不应描述为“用大模型做供应商推荐”。面试时可以如实说明：先根据自己参与过的供应商资源维护和资格初筛工作，整理出最小流程与字段；再借助 Codex 辅助编写 Streamlit 页面、文件读取和校验逻辑；根据实际业务语境审阅评分含义、修正文案，并明确哪些结论必须由人和原始材料确认。对代码生成结果仍需逐项检查并通过本地运行场景确认。
